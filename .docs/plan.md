# План реализации приложения для школьных конкурсов

Дата фиксации: 09.11.2026.

Статус: реализована первая рабочая версия 0.1.0; текущая проверка и состояние поставки описаны в [progress.md](progress.md).

Основание: [исходное ТЗ](task.md) и уточнения пользователя в обсуждении. При расхождениях с исходным ТЗ применяются уточнения, зафиксированные здесь.

## 1. Назначение и стек

Локальное Windows-приложение с русским интерфейсом для учителей и организаторов школьных конкурсов. Пользователь создаёт мероприятия и конкурсы, добавляет участников, назначает команды, вводит баллы и получает финалистов в пяти видах зачёта.

- Python 3.14, PySide6.
- SQLite и SQLAlchemy Core, без ORM.
- openpyxl для шаблонов, импорта и экспорта Excel (.xlsx).
- uv, pyproject.toml и uv.lock для окружения и зависимостей.
- pytest и pytest-qt для проверок.
- PyInstaller и Inno Setup 6 для выпуска приложения.

В начале разработки закрепить совместимые версии зависимостей и проверить пробную сборку exe на Windows без установленного Python.

Разделить приложение на интерфейс, прикладные операции, независимые функции расчёта результатов и слой хранения. Интерфейс обращается к прикладным операциям; правила ввода и целостности проверяются также вне GUI.

## 2. Модель данных

| Сущность | Данные и ограничения |
| --- | --- |
| Мероприятие | Название, дата начала, организатор |
| Конкурс | Название, мероприятие, порядок отображения |
| Команда | Обязательный номер, необязательное название, мероприятие; номер уникален внутри мероприятия |
| Участник | ФИО, школа, класс, категория 1–11, мероприятие, необязательная ссылка на команду |
| Оценка | Участник, конкурс, целое неотрицательное число; одна оценка на пару «участник — конкурс» |
| Результаты | Рассчитанные строки зачётов с местом и баллами; сохраняются и полностью восстанавливаются из исходных данных |

Все сущности имеют внутренние идентификаторы. Участник, его команда и конкурсы, по которым ему назначены оценки, должны принадлежать одному мероприятию. Использовать ограничения БД, внешние ключи SQLite и транзакции.

### Участники и команды

- ФИО, школа и класс обязательны. Школа хранится одной строкой вместе с городом, например «289 СПб».
- Совпадение ФИО допустимо: участники различаются по внутреннему идентификатору.
- Категория автоматически определяется из класса, например «9в» → 9, и допускает ручную корректировку. Если определить её невозможно, требуется указать значение 1–11.
- Команда определяется номером внутри мероприятия независимо от школы. Одинаковые названия при разных номерах не объединяют команды.
- Название хранится у команды, а не у каждого участника. Его изменение отражается во всех представлениях и экспорте.
- Отображение команды: «№ 3 — Название»; без названия — «№ 3».
- При ручном добавлении и импорте участника команда необязательна.
- Перед сохранением балла участнику без команды запросить выбор существующей команды или создание новой. При создании номер обязателен, название необязательно.
- При отмене выбора команды балл не сохраняется, прежнее состояние ячейки восстанавливается.
- При наличии оценок участника можно перевести в другую команду, но нельзя оставить без команды.

### Баллы и результаты

- Разрешены только целые неотрицательные баллы, включая 0.
- Пустая ячейка учитывается как 0, но визуально остаётся пустой. Явно введённый ноль отображается как «0».
- Очистка оценки удаляет введённое значение и возвращает ячейку в незаполненное состояние.
- Места определяются по трём лучшим различным результатам: 100, 100, 90, 80 → 1, 1, 2, 3.
- Все участники или команды с одинаковым результатом разделяют место. Число финалистов может быть больше трёх.
- Нулевые результаты могут стать призовыми. Если все оценки пусты, участники разделяют первое место с отметкой о предварительных результатах.
- Участники без команды присутствуют в общем индивидуальном зачёте, зачёте по категориям и зачётах по конкурсам; в командных группах отсутствуют до назначения команды.
- После изменения оценок, команды, категории или состава конкурсов обновлять результаты. Сохранение исходных изменений и производных результатов выполнять атомарно.
- При открытии вкладки результатов обеспечивать актуальность расчётов; результаты не должны зависеть от текущего фильтра таблицы участников.

### Пять видов зачёта

1. **Командный:** сумма баллов всех участников команды по всем конкурсам; одна карточка финалистов среди команд.
2. **Общий индивидуальный:** сумма баллов участника по всем конкурсам; одна карточка.
3. **По категориям:** сумма баллов участника по всем конкурсам; отдельная карточка для каждой представленной категории.
4. **Внутри команд:** сумма баллов участника по всем конкурсам; отдельная карточка для каждой команды с участниками.
5. **По конкурсам:** балл участника за конкретный конкурс; отдельная карточка для каждого конкурса.

При отсутствии участников или конкурсов показывать соответствующее пустое состояние. Команды без участников не включать в распределение мест.

## 3. Интерфейс

### Главный экран

- Крупное приветствие и поясняющая строка по центру.
- Под приветствием цифровые часы «ЧЧ:ММ:СС», ниже текущая дата. Использовать местное время компьютера, обновлять каждую секунду без блокировки интерфейса.
- Далее две основные кнопки: «Создать мероприятие» и «Все мероприятия».
- В нижней части главного экрана показывать текущую версию приложения и второстепенную кнопку «Что нового в этой версии». По нажатию открывать окно с номером текущей версии и понятным списком новых возможностей, изменений и исправлений. Текст поставлять вместе с приложением, чтобы он был доступен без интернета.
- Фоном — крупный логотип с сохранением пропорций, приглушённый белым полупрозрачным слоем. Текст и элементы управления должны оставаться хорошо читаемыми.

Рекомендованный текст по умолчанию, отдельно пользователем ещё не выбран:

> Добро пожаловать в мир талантов!
>
> Создавайте конкурсы, отмечайте достижения, открывайте новые имена.

Другие предложенные варианты приветствия:

- «Каждому таланту — возможность проявить себя!» / «Ваш помощник в организации школьных конкурсов.»
- «Большие достижения начинаются здесь!» / «Всё для проведения конкурсов и подведения итогов.»
- «Добро пожаловать!» / «Программа управления школьными конкурсами приветствует вас.»

### Мероприятия

- Справа вверху на всех основных экранах доступна постоянная кнопка «Путеводитель по приложению». Она открывает локальный гайд для учителей и организаторов с оглавлением, последовательной навигацией и пошаговыми инструкциями, соответствующими названиям кнопок и правилам приложения.

- Создание: поля «Название», «Дата начала мероприятия», «Организатор».
- После сохранения открыть мероприятие.
- В списке мероприятий показывать дату, название и организатора; обеспечить открытие и редактирование.
- Экран «Все мероприятия» оформлять таблицей «Дата начала», «Название», «Организатор» с выделением всей выбранной строки. Над таблицей — «Выберите нужное мероприятие». «Открыть» и «Редактировать» доступны только при выборе строки; после снятия выделения отключаются. Сохранить открытие двойным щелчком и сортировку колонок.
- Внутри мероприятия две вкладки: «Проведение конкурса» и «Результаты конкурса».

### Проведение конкурса

- Таблица: команда с номером и названием, ФИО, школа, класс, категория и динамические столбцы конкурсов.
- При наличии хотя бы одного конкурса после его столбцов показывать вычисляемую колонку «ИТОГО»: сумма баллов участника по всем конкурсам, пустые оценки считаются нулём. Колонка недоступна для ручного ввода, обновляется после сохранения или очистки любой оценки и допускает числовую сортировку.
- Над таблицей мгновенный поиск по подстроке ФИО без учёта регистра.
- На одной строке с поиском — фильтр по категории: «Все категории» и категории участников мероприятия по возрастанию. Поиск и категория применяются одновременно. Список обновляется после изменения состава участников и их категорий; выбранная категория сохраняется, пока представлена в мероприятии.
- Действия: добавить участника, импортировать Excel, скачать шаблон, управлять конкурсами и командами.
- По двойному щелчку по ФИО открывать форму участника: ФИО, школа, класс, категория, выбор команды. Кнопки «Сохранить» и «Отмена».
- Управление командами: создание и редактирование номера и названия; повтор номера внутри мероприятия запрещён.
- Баллы редактируются непосредственно в ячейках и сохраняются после подтверждения ввода.
- Реализация таблицы через QTableView, QAbstractTableModel и QSortFilterProxyModel. Изменения адресуются по идентификаторам, в том числе при активной фильтрации и сортировке.
- Ошибки ввода показывать рядом с действием; при ошибке записи не показывать несохранённые изменения как успешно сохранённые.

### Результаты

- Прокручиваемые группы карточек для пяти видов зачёта.
- Компактная адаптивная сетка: по две карточки в строке, при недостаточной ширине — одна. Командный и общий индивидуальный зачёты расположены рядом. Места выделены золотистым, серебристым и бронзовым фоном строк с сохранением текстовых подписей.
- В карточке: место, участник или команда, баллы. Для различения однофамильцев дополнительно показывать школу и класс.
- В заголовках командных карточек и строках командного зачёта показывать номер и необязательное название команды.
- При наличии незаполненных оценок выводить: «Предварительные результаты: незаполненные баллы учитываются как 0».

## 4. Excel

### Шаблон и импорт

- Формат первой версии — .xlsx.
- Обязательные колонки: «ФИО», «Школа», «Класс».
- Необязательные колонки: «Категория», «Номер команды», «Название команды».
- Незаполненные поля команды допустимы; назначение команды выполняется организатором позднее, обязательно до сохранения баллов.
- Название команды без номера требует исправления в предпросмотре.
- Перед импортом показывать предпросмотр с номерами строк, найденными ошибками и предполагаемыми командами. Дать возможность исправить данные или исключить строки.
- Категорию подставлять из класса; если определить её нельзя, требовать исправление.
- Полностью пустые строки игнорировать.
- Команды сопоставлять по номеру внутри мероприятия. Пустое название в файле не стирает существующее. Различающиеся непустые названия одного номера требуют выбора единого названия до импорта.
- Возможные дубли участников показывать как предупреждения с возможностью исключения строк, без автоматического объединения.
- После исправления ошибок добавлять выбранные строки одной транзакцией. При сбое не оставлять частично импортированные данные.
- Импорт первой версии загружает участников и сведения об их командах, а не оценки конкурсов.

### Экспорт результатов

- Один .xlsx: лист участников и оценок плюс пять листов по видам зачёта.
- Группы категорий, команд и конкурсов внутри соответствующих листов имеют отдельные заголовки.
- Указывать номер и, при наличии, название команды.
- Включать дату формирования и отметку о незаполненных оценках.
- Экспортировать данные всего мероприятия независимо от текущего поиска в интерфейсе.

## 6. Хранение и поставка

- Установленная версия: `%LOCALAPPDATA%\SchoolContests\data\contests.sqlite3`.
- Установка для текущего пользователя без обязательных прав администратора. Обновление приложения сохраняет данные.
- При запуске установщика определять наличие установленного приложения и его версию. Если выполняется обновление, до начала установки явно показывать переход, например: «Обновление с версии 0.1.0 до версии 0.2.0». При первой установке показывать устанавливаемую версию без сообщения об обновлении. Повторная установка той же версии не должна обозначаться как обновление.
- Версия приложения, версия установщика и номер версии в окне «Что нового» должны совпадать; вести описание изменений для каждого выпуска.
- Переносная версия: БД в папке `data` рядом с exe. При отсутствии прав записи показывать понятную ошибку с предложением перенести папку в доступное место.
- В разработке: БД внутри локальной папки проекта, исключённой из Git.
- Предусмотреть создание резервной копии и восстановление. Перед восстановлением и миграцией схемы автоматически сохранять текущую БД.
- Исключить одновременное открытие одной БД несколькими экземплярами приложения.
- Собирать PyInstaller в режиме onedir, поставлять установщик Inno Setup 6 и отдельный архив переносной версии.
- Приложение должно работать без установленного Python, Excel и подключения к интернету.

## 7. Этапы реализации

1. **Каркас и пробная сборка:** структура пакета, зависимости, окно, SQLite, пакетные ресурсы, проверка exe на Windows без Python.
2. **Данные:** схема БД, транзакции, мероприятия, конкурсы, команды, участники, сохранение и повторное открытие.
3. **Проведение:** таблица, поиск, формы, управление командами, ввод оценок с обязательной проверкой команды.
4. **Расчёты:** пять зачётов, общая функция распределения мест, сохранение результатов и карточки.
5. **Excel:** шаблон, предпросмотр и проверка импорта, экспорт всех зачётов.
6. **Оформление:** главный экран с приветствием, часами и фоновым логотипом; кнопка «Что нового в этой версии» и окно изменений; создание и подключение иконки.
7. **Поставка:** резервные копии, миграции, установщик с отображением исходной и новой версии при обновлении, переносная сборка, проверка обновления и инструкция пользователя.

## 8. Проверки и критерии приёмки

- Расчёты пяти зачётов: равенство результатов на призовых местах, менее трёх участников, все результаты равны, пустые оценки и явные нули.
- Перерасчёт после смены команды, категории, баллов и состава конкурсов.
- Команды с названием и без него; запрет повторного номера; независимость одинаковых названий при разных номерах.
- Изменение названия команды отражается во всех представлениях и экспорте.
- Запрет сохранения баллов без команды, корректная отмена запроса команды, запрет дробных и отрицательных оценок.
- Редактирование нужного участника при активном поиске и сортировке.
- Импорт без команды, неверные строки, конфликты названий, совпадающие ФИО, исключение строк и откат транзакции при сбое.
- Экспорт всех данных мероприятия независимо от поиска; правильные места, команды и отметки о предварительных результатах.
- Часы обновляются без блокировки интерфейса; логотип сохраняет пропорции и не мешает чтению при изменении размера окна и масштаба Windows.
- Иконка отображается у установленного приложения, окна, панели задач, exe и ярлыков.
- Данные сохраняются после перезапуска, обновления и восстановления резервной копии.
- При обновлении установщик до начала установки показывает правильные исходную и новую версии; первая и повторная установка той же версии не обозначаются как обновление.
- Кнопка «Что нового в этой версии» доступна на главном экране; окно показывает изменения текущего выпуска без подключения к интернету. Номер версии совпадает в приложении, установщике и окне изменений.
- Полный сценарий на Windows без Python и Excel: установка → мероприятие → импорт участников → команды → конкурсы → баллы → результаты → экспорт Excel.

## 9. Границы первой версии и допущения

- Автономная работа на одном компьютере; без сетевой синхронизации и учётных записей.
- Дипломы, PDF-печать и импорт старого формата .xls не входят в первую версию.
- Номер команды трактуется как положительное целое число.
- Рекомендованный вариант приветствия используется по умолчанию до другого выбора пользователя.
- Логотип перенесён в пакет приложения; созданы PNG-иконка и ICO с размерами 16–256 пикселей.
