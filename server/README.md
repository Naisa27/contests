# Сервис обратной связи Contests

Отдельный сервер принимает `POST /feedback` от настольного приложения и отправляет письмо на **r-r-y@yandex.ru** с темой **«Contests. Обратная связь из приложения»**. Получатель и тема фиксированы на сервере; клиент не может использовать его для рассылки на другие адреса.

**Сервис подготовлен к размещению, но ещё не развёрнут.** В приложении `resources/feedback.json` пока содержит пустой адрес. Пока адрес не настроен, отправка честно сообщает о недоступности и не показывает успех.

## Что понадобится

- Сервер или хостинг с Python 3.12+ и uv, доступом к исходящему SMTP по порту 465.
- Домен с HTTPS и обратный прокси перед сервисом (например, nginx).
- Пароль приложения Яндекс Почты, созданный владельцем ящика. Он задаётся только в серверном окружении, не передаётся пользователям и не включается в Git, ресурсы или exe.

Для SMTP Яндекс указывает `smtp.yandex.ru`, SSL, порт 465 и пароль приложения. Настройка доступа почтовых программ и создание пароля описаны в [справке Яндекса](https://yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others).

## Запуск на сервере

Из корня репозитория перейдите в `server`. Скопируйте `.env.example` в `.env`, заполните `FEEDBACK_SMTP_PASSWORD`. При необходимости измените SMTP-логин и адрес отправителя на разрешённые для вашего почтового аккаунта. Получатель письма останется фиксированным.

```text
cd server
uv sync
uv run --env-file .env python app.py
```

Сервис слушает `127.0.0.1:8080`; процесс должен быть настроен как постоянная служба вашим хостингом или системным администратором. Сам файл `.env` автоматически Python не читает: в приведённой команде его загружает uv. В production можно вместо файла задать переменные окружения в панели хостинга или менеджере служб.

## HTTPS и IP отправителя

Публикуйте только HTTPS-адрес, например `https://ваш-домен/feedback`. Настройку сертификата выполните средствами хостинга. Пример расположения обработчика в уже настроенном HTTPS-блоке nginx:

```nginx
location = /feedback {
    client_max_body_size 64k;
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 60s;
}
```

`FEEDBACK_TRUSTED_PROXY=127.0.0.1` нужен, если nginx находится на том же сервере. При другой схеме укажите конкретный адрес доверенного прокси; `*` запрещён. Не открывайте внутренний порт сервиса в интернет. Прокси должен перезаписывать указанные заголовки, а не доверять присланным пользователем значениям. Для нескольких прокси требуется отдельно настроить цепочку доверия; текущий пример рассчитан на один.

Письмо содержит адрес `REMOTE_ADDR`, установленный Waitress, а не поле IP из клиентского JSON. При корректной настройке прокси это внешний адрес пользователя. При VPN, NAT или корпоративном шлюзе будет виден адрес выхода в интернет. Заголовок письма Received может при этом показывать адрес SMTP/сервиса — клиентский IP указан отдельно в тексте.

[Waitress: настройки доверенного прокси](https://docs.pylonsproject.org/projects/waitress/en/stable/arguments.html#trusted-proxy).

## Подключение настольного приложения

Для локальной проверки задайте переменную окружения `SCHOOL_CONTESTS_FEEDBACK_URL` с полным HTTPS-адресом сервиса и запустите приложение. Для распространения установщика запишите этот адрес в `src/school_contests/resources/feedback.json` и выполните новую сборку. Секреты в этом файле не нужны.

```json
{
  "endpoint": "https://ваш-домен/feedback"
}
```

Окно и поля формы доступны офлайн, но отправка требует интернета. Подтверждение появляется только после ответа сервиса о приёме письма SMTP-сервером. Это подтверждение отправки, а не прочтения адресатом или гарантированного попадания во «Входящие».

## Проверка перед распространением

1. Настройте сервис и HTTPS, затем отправьте одно тестовое сообщение из приложения с согласованного тестового компьютера.
2. Убедитесь, что письмо пришло на нужный адрес и имеет точную тему, сообщение, имя/контакт при заполнении, версию и правильный внешний IP. Если письма нет, проверьте папку «Спам» и настройки отправителя.
3. Проверьте отказ при недоступном SMTP: в приложении не должно быть сообщения об успехе, введённый текст должен остаться.
4. Сохраните адрес в пакетных ресурсах и соберите установщик заново.

Автоматические тесты репозитория используют подмену почтового отправителя и не отправляют реальные письма.

## Ограничения и эксплуатация

Ограничены размер тела запроса (64 КиБ), длина сообщения (10 000 символов), число обращений с одного IP (10 за 10 минут) и общее число попыток (120 за час). Отправки с одинаковым идентификатором и тем же содержимым не повторяются в течение 24 часов работы процесса. При изменении содержимого тот же идентификатор отклоняется. При ошибке SMTP повторная попытка разрешается.

Идентификаторы, хеши запросов и счётчики хранятся в памяти одного процесса и сбрасываются при перезапуске. Не запускайте несколько независимых экземпляров без общего хранилища ограничений и квитанций. Сбой процесса между приёмом письма SMTP-сервером и сохранением квитанции всё же может привести к повтору. Если требуется повышенная надёжность или масштабирование, квитанции и очередь следует перенести в постоянное хранилище.

Сервис не сохраняет тексты сообщений в файлы и не печатает SMTP-пароль в журнал. Содержимое отправленного письма будет храниться в почте получателя. До публичного размещения установите ограничения и мониторинг на уровне хостинга с учётом ожидаемого числа пользователей.
